НАЗВАНИЕ И ФИЛОСОФИЯ
NovaX — «новая звезда» в мире микроядер. Ядро — «Heart» (сердце),
потому что оно качает IPC-кровь между серверами-органами.
Принципы:
  1. В ядре только то, что невозможно вынести в userspace.
  2. IPC — центральный примитив. Всё остальное строится поверх IPC.
  3. Capability-based security: никаких «root», только токены.
  4. Детерминизм: одинаковый вход → одинаковый выход. Никаких скрытых
     глобалов в планировщике.
  5. Fail-fast: ошибки ядра = kernel panic с полным дампом.
     Никаких silent degradation.
  6. Минимум строк — максимум смысла. Никакого копипаста.

ЧТО ВХОДИТ В ЯДРО (Heart) — обязательный минимум
  - Boot: UEFI (x86_64) через limine bootloader protocol.
  - Память: physical frame allocator (bitmap), virtual memory
    manager (4-level paging), kernel heap (slab или buddy),
    copy_from_user/copy_to_user, demand paging.
  - Планировщик: preemptive, multi-priority, SMP-aware (APIC + IPI),
    round-robin внутри приоритета. Классический O(1) или CFS-lite.
  - Потоки и процессы: thread control block, process control block,
    fork/exec (упрощённо), context switch на ассемблере.
  - IPC (ядро!): синхронный message-passing, fast-path через
    syscall, медленный через shared memory + notification.
    Не более 64 байт inline, остальное — capability на memory object.
  - Capabilities: CSpace (capability space), права read/write/grant/revoke,
    передача capability через IPC.
  - Syscalls: минимальный набор — send, recv, call, reply, yield,
    map, unmap, spawn, exit, invoke_capability. Всё остальное — в userspace.
  - Прерывания: IDT, обработчики, делегирование драйверам
    через userspace IRQ-серверы.
  - Таймеры: LAPIC timer, HPET, TSC calibration.
  - SMP: bootstrap AP через INIT-SIPI, per-CPU структуры, атомики.

ЧТО ВЫНОСИТСЯ В USERSPACE — обязательный минимум
  - Init server (аналог init): стартует первым, спавнит остальных.
  - VFS server: дерево файлов, монтирование.
  - Device manager server: PCI enumeration, загрузка драйверов.
  - Драйверы как серверы:
      - serial (UART 16550)
      - PS/2 keyboard
      - virtio-net, virtio-blk (для QEMU)
      - framebuffer (через limine)
  - Shell server: минимальный shell на Rust, общается через IPC.
  - RAM FS server: простейшая ФС в памяти.
  - Все серверы — Rust, no_std, статические бинарники.

ЯЗЫК И ИНСТРУМЕНТЫ
  - Rust: edition 2021+, no_std, никакого std.
  - Target: x86_64-unknown-none (или кастомный target JSON).
  - Bootloader: limine (или собственный UEFI-загрузчик на Rust).
  - Ассемблер: inline asm или отдельные .S файлы для context switch,
    IDT, syscall entry, gdt/tss setup.
  - Сборка: cargo + build.rs + кастомный линкер-скрипт.
  - Тесты: unit-тесты в no_std через custom test framework,
    интеграционные — в QEMU с автоматическим сравнением вывода.
  - Отладка: GDB через QEMU -s -S, serial-логи, kernel debug-логгер.
  - CI: GitHub Actions с QEMU, автоматический запуск на каждый commit.

АРХИТЕКТУРА КОДА
Разложить по workspace-крейтам:
  novax/
    kernel/
      heart/        — планировщик, потоки, процессы
      memory/       — paging, allocator, VMM
      ipc/          — messages, endpoints, capabilities
      syscall/      — таблица, entry, dispatch
      arch/x86_64/  — boot, GDT, IDT, TSS, APIC, SMP

      vfs/
      devmgr/
      shell/
      ramfs/

        ps2_kbd/
    common/
      novax_abi/    — общие типы, syscall-номера, IPC-структуры

    tools/
      mkiso/        — упаковка ISO
      qemu_run/     — запуск для отладки

ПРИНЦИПЫ КОДА
  - Каждая подсистема — отдельный модуль с чётким API.
  - Никаких `unsafe`, где можно обойтись. Где нельзя — минимум,
    изолированно, с комментариями WHY, а не WHAT.
  - Ошибки — через Result<T, E>, E — enum с конкретными вариантами.
  - Логи — структурные, с уровнями (error/warn/info/debug/trace).
  - Комментарии — только там, где не очевидно. Код должен
    читаться сам.
  - Никаких глобальных мутабельных переменных без явной причины.
    Где нужны — через SpinLock/RwLock/OnceCell.
  - Все публичные API документированы rustdoc.
