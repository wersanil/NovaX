## 3. Архитектурные принципы NovaX
**NovaX** — микроядерная ОС, где ядро (**Heart**) качает IPC-кровь между изолированными серверами-органами.
1. **Минимализм ядра:** В ядре остаётся только то, что физически невозможно вынести в userspace.
2. **IPC-центричность:** Синхронный/асинхронный IPC — базовый примитив ядра; все системные сервисы строятся поверх него.
3. **Capability-based security:** Никакого понятия `root` или ambient authority — доступ контролируется исключительно через непрозрачные capability-токены.
4. **Детерминизм:** Одинаковый вход → одинаковый выход. Никаких скрытых глобальных состояний в планировщике.
5. **Fail-fast:** Критическая ошибка ядра = немедленный `kernel panic` с полным дампом регистров и стека. Никакой молчаливой деградации.
6. **Zero Bloat:** Минимум строк — максимум смысла. Никакого копипаста.

```text

├── kernel/
│   ├── heart/       # планировщик, потоки, процессы, syscalls, ipc, arch/x86_64, drivers_builtin, debug

│   └── ipc/         # messages, endpoints, capabilities

│   ├── vfs/         # виртуальная файловая система

│   ├── shell/       # командная оболочка

│   └── drivers/     # virtio_net, virtio_blk, ps2_kbd
├── common/
│   ├── novax_abi/   # структуры ABI, номера syscalls, контракты IPC
│   └── libnovax/    # стандартная библиотека userspace поверх syscalls
```

## 5. Дорожная карта (Строгий порядок выполнения)
Не переходи к следующему этапу, пока текущий не подтвержден чистым прогоном в QEMU без регрессии предыдущих этапов и пока ты не отчитался пользователю в чате:
- [x] **Milestone 0:** Boot to serial output.
- [x] **Milestone 1:** Память (`physical frame allocator`, `4-level paging`, `kernel heap`, тесты).
- [x] **Milestone 2:** Прерывания и таймеры (`GDT`, `IDT`, `TSS`, `LAPIC timer`, обработчики IRQ).
- [x] **Milestone 3:** Планировщик и потоки (`TCB`, `context switch` на asm, `round-robin`).
- [x] **Milestone 4:** Userspace (`syscall/sysret`, переход в Ring 3, `ELF loader`).
- [ ] **Milestone 5 (ТЕКУЩИЙ):** IPC (`endpoints`, `messages`, `capabilities`, обмен `ping` между userspace-процессами).
- [ ] **Milestone 6:** Драйверы как userspace-серверы (`serial` и `PS/2 keyboard` в userspace, проброс IRQ через IPC).
- [ ] **Milestone 7:** Init и shell (`init server`, `shell server`, выполнение `echo hello` через IPC).
- [ ] **Milestone 8:** SMP (`APIC`, `IPI`, запуск второго ядра, параллельное планирование на двух CPU).
- [ ] **Milestone 9:** Virtio (`virtio-net` драйвер в userspace, рабочий `ping` по сети из QEMU).

## 6. Стандарты кода и строгие запреты
- **Окружение:** Rust edition 2021+, `#![no_std]`, target `x86_64-unknown-none`. Использование `std` строго запрещено. Использование `alloc` допускается только там, где это архитектурно обосновано.
- **Дисциплина `unsafe`:** Избегай `unsafe` везде, где возможно. Каждый `unsafe`-блок обязан быть минимальным, изолированным и сопровождаться комментарием `// WHY:` с объяснением инвариантов безопасности (почему это безопасно, а не что делает код).
- **Обработка ошибок:** Только через `Result<T, E>`, где `E` — строгий `enum` с конкретными вариантами ошибок. Не маскируй ошибки ядра через `.unwrap()` без явной причины.
- **Синхронизация и глобалы:** Никаких `static mut`. Разделяемое состояние оборачивается только в `SpinLock`, `RwLock` или `OnceCell`.
- **Логирование и документация:** Структурные логи с уровнями (`error`, `warn`, `info`, `debug`, `trace`). Все публичные API и контракты `novax_abi` документируются через `rustdoc` (`///`).
- **ЗАПРЕЩЕНО:**
  - Копировать код из xv6, Redox или других ОС напрямую (разрешены только архитектурные идеи).
  - Оставлять `TODO` без пояснения причины и ссылки на соответствующий Milestone.
  - Упрощать архитектуру ради скорости написания («костыли» вместо IPC/capabilities).
  - Использовать VGA text mode для вывода «Hello World» (только `serial`, затем `framebuffer` через Limine).

## 7. Протокол закрытия Milestone и формат отчета пользователю
**ОБЯЗАТЕЛЬНО:** Как только текущий Milestone успешно собран и проверен в QEMU, обнови `agen_mem.txt`, **напиши пользователю в чат** и **останови выполнение** до получения дальнейших указаний.

Отчет пользователю оформляй строго по следующей структуре:
1. **Статус и поздравление:** Короткое сообщение об успешном завершении Milestone (с подтвержденным выводом из `qemu_out.log`).
2. **Цель Milestone:** Что именно должно было заработать на этом этапе.
3. **Архитектурные решения:** Обоснование выбранных структур данных, ABI и протоколов.
4. **Структура файлов:** Список созданных и измененных файлов.
5. **Код:** Полный, компилируемый код с `Cargo.toml` — **без сокращений и многоточий (`...`)**.
6. **Как проверить:** Точные команды сборки/запуска QEMU и фактический лог вывода.
7. **Известные ограничения:** Что сознательно не вошло в текущий этап.
8. **Что дальше:** Анонс следующего Milestone и запрос подтверждения на старт работ.

## 8. Текущий контекст и стартовый алгоритм действий
**Контекст:** Завершается **Milestone 5 (IPC)**. В `syscall_entry` (asm) только что исправлен критический баг, где код возврата `rax` затирался указателем на стек пользователя (исправлено на `r10`).

**Выполни последовательно прямо сейчас:**
1. Проинспектируй актуальную структуру файлов проекта (строго исключая `boot/limine` и `target`, например: `find kernel userspace common tools -maxdepth 4`) и прочитай `agen_mem.txt` (если он уже существует), чтобы свериться с текущим состоянием кода.
2. Создай или обнови `agen_mem.txt` в корне проекта с фиксацией актуального дерева файлов, статуса завершения M5 и фикса `r10` в `syscall_entry`.
3. Собери ядро: `cargo build --release -p novax_heart`.
4. Собери загрузочный образ: `./tools/mkiso.sh`.
5. Запусти QEMU с таймаутом для снятия лога: `timeout 15s ./tools/qemu_run.sh > qemu_out.log 2>&1 || true`.
6. Прочитай `qemu_out.log`:
   - **Если видишь** `server: waiting for message`, `client: sending ping` и `server: got message: ping` без паник — обнови `agen_mem.txt` (отметь M5 как завершенный), **остановись и напиши пользователю в чат** полный отчет о закрытии Milestone 5 и проектировании Milestone 6 по формату из раздела 7 (не начинай писать код M6 до ответа пользователя).
   - **Если в логе есть `Kernel Panic` или зависание** — проанализируй дамп, исправь причину в коде, пересобери и повтори прогон QEMU до полного прохождения M5.
